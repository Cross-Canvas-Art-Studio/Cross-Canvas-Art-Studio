## 2025-08-10 - CPU waste in cryptographic functions for empty/unusable hashes
Learning: In low-level security routines, developers often generate standard cryptographically secure hashes (such as `bcrypt.hashpw` with standard work factor rounds = 12) for guest or passwordless placeholders to ensure a non-null hash field. This is an enormous CPU bottleneck (taking ~350ms of synchronous blocking time per call) and serves no cryptographic purpose since the hash is intentionally prepended with an invalid prefix (e.g., '!!') to render it unusable.
Action: Avoid running computationally intensive hashing functions for unusable passwords. Use static or cheap random strings with invalid prefixes (like '!!unusable-' + uuid) to achieve over 300,000x speedups safely without blocking the main event loop.
